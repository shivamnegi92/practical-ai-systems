# Image caption QC

Run rule-based checks on autogenerated image captions: placeholder phrases, length bounds, and required keyword coverage.

**Level:** intermediate · **Runs locally:** yes · **Credentials:** none · **Dependencies:** Python standard library only

## Quickstart

Run from the repository root:

```bash
python3 -m systems.caption_qc.app "A golden retriever running across a sunny beach." --require retriever --require beach
```

## Evaluate and test

```bash
python3 -m systems.caption_qc.evaluate
python3 -m unittest systems.caption_qc.test_caption_qc
```

The evaluation uses the small synthetic dataset shipped in this folder. Results describe this implementation on those fixtures only; they are not general performance claims.

## Results snapshot

See [`eval/results.json`](eval/results.json) for current QC accuracy on 5 synthetic captions covering a clean pass, a banned placeholder phrase, a too-short caption, a too-long caption, and a generic failure message.

## Known limitations

- Placeholder and required phrase checks ignore case and repeated whitespace, and require word boundaries. Thus `car` does not match `scarf`, while `(car)` matches. Phrases are literal, including punctuation; empty required phrases are unsatisfied. This is still lexical matching, not semantic or visual verification.

- This never looks at the image; a fluent, well-formed caption that is simply wrong about the image's content will still pass.
- The banned-phrase and length-bound lists are small and arbitrary; expand them for your own caption pipeline before relying on this.
- Synthetic data is not representative of real production traffic. Expand and independently label cases before relying on these results.
